# 검사 입력

－ 검사 입력은 생산된 히트·슬래브·코일 LOT의 측정값을 입력하면, 시스템이 기준에 맞춰 합격·불합격을 자동 판정하고 그 결과를 재고·예약·불합격 관리로 넘기는 화면입니다.

## 1. 목적·사용 역할·필요 권한

### 목적

- 제강·연주·열연 실적으로 만들어진 히트·슬래브·코일 LOT을 검사 대기열에서 골라 측정값을 입력한다 (REQ-QC-001).
- 검사 항목과 기준은 시스템이 정한다. 히트는 강종 성분 규격, 슬래브·코일은 지금 적용 중인 검사 기준 버전을 쓴다 (REQ-QC-002).
- 저장하면 서버가 항목마다 “최소 ≤ 측정값 ≤ 최대”(경계 포함)로 합격·불합격을 자동 판정한다. 사람이 판정을 바꾸지 않고, 재검사는 없다 (REQ-QC-003).
- 판정 결과는 검사 등록과 같은 트랜잭션에서 재고·자동 예약(합격), 불합격 관리·배정 해제(불합격), 생산계획 상태, 알림, 작업 로그에 반영된다 (REQ-QC-003, REQ-INV-007).
- 검사 대기 LOT에 품질 담당자와 검사 마감을 지정해, 대시보드 “처리 필요”에서 급한 검사부터 처리하게 한다.

### 사용 역할

| 역할 | 쓰는 방식 | 들어오는 길 |
| --- | --- | --- |
| 품질 (주 사용자) | 검사 대기 LOT을 골라 측정값을 입력하고 판정 결과를 확인한다. 품질 담당자·검사 마감을 지정한다 | 왼쪽 메뉴 “검사 입력”, 대시보드 “처리 필요”, 검사 대기·담당 지정 알림 |
| 생산 | 자기 실적으로 나온 LOT의 검사 진행·판정 결과를 본다 (불합격 뒤 재생산 판단용) | 메뉴에는 없음. 불합격 알림, 생산계획·공정 실적 화면의 링크 |
| 관리자 | 검사 현황을 확인한다 | 메뉴에는 없음. 링크·주소로 직접 |
- 영업·구매·물류는 이 화면을 쓰지 않는다. 주소로 들어오면 “권한 없음” 화면이 나온다.

### 필요 권한

| 동작 | 필요한 권한 | 기본값으로 가진 역할 |
| --- | --- | --- |
| 검사 대기열·검사 결과 조회 | INSPECTION_REGISTER 조회(VIEW) 이상 | 품질(사용), 생산(조회), 관리자(조회) |
| 측정값 등록 (자동 판정) | INSPECTION_REGISTER 사용(USE) | 품질 |
| 품질 담당자·검사 마감 지정 | INSPECTION_REGISTER 또는 DISPOSITION_SET 사용(USE) | 품질 |
| 담당자 후보 목록 조회 | INSPECTION_REGISTER 또는 DISPOSITION_SET 조회(VIEW) 이상 | 품질, 생산, 관리자 |
- 사용 권한이 없으면 등록·지정 버튼은 비활성이고 “권한이 필요해요”를 보여 준다. 서버도 같은 권한을 다시 확인하고, 없으면 COM-002를 돌려준다.
- 담당자는 사용 중인 품질 역할 사원만 고를 수 있다.
- 검사 기준 자체를 바꾸는 것은 이 화면이 아니라 “검사 기준” 메뉴(INSPECTION_STANDARD_MANAGE)에서 한다.
- 권한은 역할별 기본값이며 관리자가 “부서·권한”에서 바꿀 수 있다 (역할별 메뉴 v2 3장).

## 2. 철강 흐름에서의 위치

### 흐름

공정 실적(제강·연주·열연) → **검사 입력** → 합격: 재고·자동 예약 → 열연 투입 또는 출하요청·출고·밀시트 / 불합격: 불합격 관리 → 생산계획(재생산)

### 받는 것

| 무엇 | 어디서 | 검사 대기열에 오는 조건 |
| --- | --- | --- |
| 히트 LOT (성분 검사) | 공정 실적 — 제강 실적 완료 시 생성 | 아직 판정 전인 히트 (연주에 투입돼 소진돼도 검사 대상) |
| 슬래브 LOT (표면·치수 검사) | 공정 실적 — 연주 실적 완료 시 생성 | 판정 전 · 미소진(재고) · 상위 히트가 불합격이 아님. 상위 히트가 판정 전이어도 먼저 검사할 수 있다 |
| 코일 LOT (치수·기계적 성질 검사) | 공정 실적 — 열연 실적 완료 시 생성 (열연 투입에서 배정한 슬래브 1매 → 코일 1개) | 슬래브와 같음 |
| 검사 항목·기준 | 히트: 기준정보 강종 성분 규격 / 슬래브·코일: 검사 기준 메뉴의 지금 적용 중인 버전 (강종 전용 + 공통) | 기준이 없거나, 필수 항목에 최소·최대가 둘 다 없으면 판정하지 않고 MST-001 |
| 표시용 연결 정보 | 생산계획·수주 품목·고객사·상위 히트 판정 | — |
| 품질 담당자·검사 마감 | 이 화면 또는 불합격 관리에서 지정 | 선택 (없어도 검사는 된다) |
- 실적 시뮬레이션(REQ-PRD-007)은 검사도 기준 안 값으로 자동 등록한다(검사자 = 시스템). 끄고 실행하면 LOT이 이 대기열에 남는다.

### 넘기는 것

| 판정 | 넘어가는 것 | 다음 화면·담당 |
| --- | --- | --- |
| 공통 | 검사 기록(검사번호, 측정값, 판정 때 기준 min·max 복사), LOT 판정(`is_passed`) | LOT 추적, 대시보드 “처리 필요”·KPI, 작업 로그(INSPECTION_REGISTERED) |
| 공통 | 생산계획 완료 여부 재계산 | 생산계획 (생산) |
| 합격 (슬래브·코일, 상위 히트도 합격) | 재고 반영 → 원래 수주 품목의 미확보 매수 안에서 자동 예약(AUTO_RESERVED) | 재고, 수주 충족 현황, 출하요청 (영업) |
| 합격 (코일 수주용 슬래브) | 필요한 매수만 열연 투입용으로 귀속(재고 풀 밖), 남는 슬래브는 여재. 생산 역할에 “열연 투입 슬래브 배정 가능” 알림 | 열연 투입 (생산) |
| 합격 (히트) | 이미 제품 검사에 합격해 있던 하위 슬래브·코일이 이때 재고에 들어가고 자동 예약된다 | 재고, 수주 충족 현황 |
| 합격 LOT 출고 때 | 히트 성분·검사 항목과 값이 밀시트 스냅샷에 복사된다 | 출고 확정·밀시트 (물류·영업) |
| 불합격 | 재고·예약·배정·출고 대상에서 빠진다. 불합격 LOT으로 등록(처리 상태 미지정), 작업 로그 REJECTED_JUDGED | 불합격 관리 (품질) |
| 불합격 (히트) | 하위 슬래브·코일도 쓸 수 없게 되고, 하위 LOT의 확정 배정(CONFIRMED)은 해제된다(ALLOCATION_RELEASED) | 불합격 관리, 출하요청 (영업) |
| 불합격 | 알림: 검사자 소속 부서(품질) → 불합격 관리, 생산 역할 → 생산계획 (재생산 판단) | 불합격 관리 (품질), 생산계획 (생산) |
- 판정과 뒤따르는 반영(재고·예약·배정 해제·계획 재계산·작업 로그)은 한 트랜잭션에서 처리된다. 중간에 실패하면 아무것도 저장되지 않고 LOT은 검사 대기로 남는다.

| 영역 | 필드 | 타입·단위 | 출처 API |

| 측정값 입력 | 입력 중 미리보기: 합격·불합격·미입력, 하한·상한과의 차이 | 화면 계산 (저장 때 판정은 서버가 한다) | — |
| 측정값 입력 | 미리보기 합계: 입력 수 / 전체 항목 수, 비어 있는 필수 항목 | 정수 / 항목명 목록 | — |
| 측정값 입력 | 등록을 막는 안내: 검사 기준이 없음 / 최소·최대가 없는 필수 항목 / 필수 측정값 미입력 / 숫자 형식 오류 / 권한 없음(“권한이 필요해요”) | 문구 (화면 판단, 등록 버튼 비활성) | 목록 응답의 `items`  • 로그인 사용자 권한 |
| 측정값 입력 | 상위 히트 판정 전 안내 (“먼저 검사할 수 있고, 히트가 합격해야 재고에 들어가요”) | 문구 | 목록 응답의 `lot.heatIsPassed` |
| 판정 결과 (등록 뒤·완료 LOT) | 시스템 판정 `inspectionResult`, 검사번호 `qualityInspectionNo`, 검사명, 검사 시각 `inspectedAt`, 검사자 `inspectorEmployeeName` | 코드 INSPECTION_RESULT / 문자열 / ISO 시각 / 없으면 "시스템" | `POST /api/v1/quality-inspections` 응답, 또는 `GET /api/v1/quality-inspections?status=done` |
| 판정 결과 (등록 뒤·완료 LOT) | 검사값 표: 항목, 기준(판정 때 저장된 min·max), 측정값 `measuredValue`와 단위, 항목 판정 `isPassed`, 기준 안 위치 | 숫자 문자열 / boolean, null = 입력 안 한 선택 항목 | 위와 같음 (`values[]`) |
| 판정 결과 (등록 뒤·완료 LOT) | 검사 메모 `memo`, 다음 LOT 검사까지 남은 건수 | 문자열 / 정수, 건 | 위와 같음 / 대기 목록 건수 |
| 검사 뒤 처리 | 판정과 함께 기록된 후속 처리: 검사·불합격·배정 해제·자동 예약 (시각, 주체 USER·SYSTEM, 이벤트 라벨, 요약) | ISO 시각 / 문자열 | `GET /api/v1/business-events?lotId=`, `?salesOrderId=&eventType=AUTO_RESERVED` (검사 시각 앞뒤로 좁힘) |
| 검사 뒤 처리 | 바로가기: 불합격 → 불합격 관리·생산계획, 합격 → 수주 | 화면 경로 | 판정 결과의 `lot` |
- 시각은 ISO 문자열이며 화면에는 한국 시간으로 표시한다. 기준·측정값은 소수 4자리까지의 숫자 문자열이고, 화면에서는 뒤의 0을 지워 보여 준다 ("0.2500" → "0.25").
- 조회 권한: 검사 목록·결과는 INSPECTION_REGISTER 조회 이상, 담당자 목록은 INSPECTION_REGISTER 또는 DISPOSITION_SET 조회 이상.

## 4. 사용자 동작 → API

| 동작 | 메서드·경로 | 요청 | 응답 | 권한·에러 |

## 5. 상태 변화·작업 로그

### 상태 변화

| 대상 (테이블·컨럼) | 언제 | 변화 |
| --- | --- | --- |
| 검사 `quality_inspection`, `quality_inspection_value` | 검사 등록 | 새로 생성. 판정 `inspection_result` = PASS 또는 FAIL, 검사자·검사 시각 저장. 항목마다 측정값·항목 판정과 함께 그때의 기준 min·max를 복사해 둔다 (기준이 나중에 바뀌어도 결과는 그대로) |
| LOT 판정 `lot.is_passed` | 검사 등록 | null(검사 전) → true(합격) 또는 false(불합격). 한 번 정해지면 바꿀 수 없다 (재검사 없음) |
| 제품 재고 `inventory.on_hand_qty` | 슬래브·코일이 적격이 될 때 (자기 검사 합격 + 상위 히트 합격 + 재고 상태) | 규격별 재고 풀 1매(1개) 증가. 코일 수주의 열연 투입용으로 귀속된 슬래브는 재고 풀에 넣지 않는다 |
| 예약 `reservation` (ACTIVE), `inventory.reserved_qty` | 적격 LOT의 원래 수주 품목에 아직 확보 못 한 매수가 있을 때 | 자동 예약 1매 생성, 예약 매수 증가. 예약하지 않은 생산분은 수주 연결을 끊어 여재(슬래브)·가용 재고로 남는다 |
| LOT 수주 연결 `lot.sales_order_item_id` | 코일 수주용 슬래브가 적격이 될 때 | 열연에 더 필요하면 코일 수주 품목에 귀속(유지), 남으면 null로 바꿔 여재가 된다 |
| 하위 슬래브·코일 | 히트 합격 | 이미 제품 검사에 합격해 있던 하위 LOT이 이때 적격이 되어 위의 재고·예약 반영을 함께 탄다 |
| 배정 `allocation` | 히트 불합격 | 하위 슬래브·코일의 CONFIRMED 배정 → RELEASED (출하·열연 배정 해제) |
| 불합격 LOT | 불합격 판정 | 재고에 들어가지 않고 예약·배정·출고 대상에서 빠진다. 처리 상태 `disposition_status`는 null(미지정)로 불합격 관리에 올라간다 |
| 생산계획 `production_plan.production_plan_status` | 판정 뒤 매번 확인 | IN_PROGRESS → COMPLETED: 앞 공정 실적이 모두 완료되고, 판정 안 끝난 LOT이 없고, (코일 계획이면) 열연까지 끝났을 때. 완료 시각을 저장하고, 시작하지 않고 남은 열연 대기 실적은 지운다 |
| 수주 품목 상태 `sales_order_item.sales_order_item_status` | 생산계획이 완료될 때 | 수주 품목 상태를 다시 계산한다 |
| 담당·마감 `lot.quality_assignee_id`, `lot.inspection_due_at` | 담당·검사 마감 저장 | 보낸 값으로 바꾼다 (null이면 지움). 판정·재고에는 영향 없음 |
- 검사 등록의 모든 변화(검사·판정·재고·예약·배정 해제·계획·작업 로그·알림)는 한 트랜잭션이다. 같은 수주 품목·LOT에 동시에 들어오는 판정은 수주 품목 → LOT 순서로 잠가 자동 예약이 겹치지 않게 한다.
- 처리가 끝나면 실시간 주제 `quality-inspections`, `lots`, `inventories`, `production-plans`를 보내 다른 화면·대시보드가 다시 조회한다.

### 작업 로그

| 이벤트 (화면 라벨) | 언제 | 주체 | 대상·연결 | 내용 |
| --- | --- | --- | --- | --- |
| INSPECTION_REGISTERED (검사) | 검사 등록마다 | USER(검사자). 실적 시뮬레이션이면 SYSTEM | 대상 = 검사(검사번호), LOT, 수주 | “HT-… 성분 검사 합격”. 항목별 측정값·기준·판정. 사유 코드 QUALITY_PASSED / QUALITY_FAILURE / SIMULATION |

| AUTO_RESERVED (자동 예약) | 적격 LOT을 원래 수주 품목에 예약할 때 | SYSTEM | 대상 = 예약(수주번호 #품목), 수주 | “검사 합격 생산분 1매를 원래 수주 품목에 자동 예약”. 재고·예약 매수 전·후. 사유 QUALITY_PASSED |
| WORK_COMPLETED (작업 완료) | 판정으로 생산계획이 완료될 때 | 검사 등록과 같음 | 대상 = 생산계획, 수주 | “생산계획 PP-… 완료 (목표 N매, 합격 N매, 미합격 N매)”. IN_PROGRESS → COMPLETED |
- 작업 로그는 본 거래와 같은 트랜잭션에서 저장된다 (REQ-LOG-001). LOT·수주 타임라인과 작업 로그 화면에서 볼 수 있다.
- 담당·검사 마감 저장은 작업 로그를 남기지 않는다 (REQ-LOG-002 이벤트 종류에 없음). 대신 새 담당자에게 알림을 보낸다.
