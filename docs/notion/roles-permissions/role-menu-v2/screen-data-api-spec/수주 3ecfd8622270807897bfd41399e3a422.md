## 1. 목적·사용 역할·필요 권한

- **목적**: 등록된 수주를 찾고, 품목별로 얼마나 채워졌는지(예약·생산중·검사합격·출하) 확인한다. 수주 수정·취소와 출하요청으로 넘어가는 출발점이다 (REQ-SO-004·005·006).
- **사용 역할**: 영업. 메뉴는 영업에게만 보인다(역할별 메뉴 2장). 생산·물류·관리자는 다른 화면에서 들어올 때 조회만 한다.
- **필요 권한**: 조회 `SALES_ORDER_CREATE` VIEW 이상 / 수정 `SALES_ORDER_CREATE` USE / 취소 `SALES_ORDER_CANCEL` USE
- 충족 현황은 별도 메뉴가 아니라 상세 화면의 탭이다.

## 2. 철강 흐름에서의 위치

- **받는 것**: 수주 등록 결과(수주·품목·ACTIVE 예약), 생산계획·실적의 진행 매수, 검사 합격 매수, 출고 확정 매수
- **넘기는 것**: 출하요청 대상 수주 품목(③ 출하요청), 취소 시 예약 해제·배정 해제·생산계획 취소·여재 전환

## 4. 사용자 동작 → API

경로는 모두 `/api/v1` 아래. 응답은 `success`, `data` / 오류는 `success`, `error.code`, `error.message` (코드 컨벤션 5장).

| 동작 | 메서드·경로 | 요청 | 응답 | 권한·에러 |
| --- | --- | --- | --- | --- |
| 목록 보기·필터·정렬 (`useSalesOrderList`) | GET `/sales-orders` 🟡 | 쿼리: status, dueRisk, customerId, itemType, dueFrom, dueTo, page, size, sort | items 배열(3장 목록 필드), page, size, total, counts | SALES_ORDER_CREATE VIEW / COM-002 |
| 행 클릭·상세 열기 (`useSalesOrderDetail`) | GET `/sales-orders/:id` 🟡 | — | 헤더 정보, 품목 목록 | VIEW / 404 |
| 충족 현황 탭 (`useFulfillment`) | GET `/sales-orders/:id/fulfillment` | — | 품목별 매수 단계·진행률·출하요청 가능 매수·불합격 알림 | VIEW |
| 생산 연결 탭 | GET `/sales-orders/:id/lots` 🟡 | — | 연결 LOT 목록 | VIEW |
| 작업 로그 탭·전체 보기 | GET `/business-events` | 쿼리: salesOrderId, page, size | 이벤트 목록 (시간순) | VIEW |
| 수정 (`useUpdateSalesOrder`) | PATCH `/sales-orders/:id` 🟡 | dueDate, remark, managerId 중 바꿀 값만 | 수정된 수주 | SALES_ORDER_CREATE USE / 수량·규격 필드는 ValidationPipe가 거부(`forbidNonWhitelisted`) |
| ⚠️ 수주 취소 (`useCancelSalesOrder`) | POST `/sales-orders/:id/cancel` | reason | 취소된 수주, 해제된 예약·배정 매수, 여재 전환 매수 | SALES_ORDER_CANCEL USE / 출고된 매수 있음 SO-003, 진행 중 출하요청 있음 SO-004 |
| 업무방 열기 | GET `/chat-rooms?salesOrderId=` | — | 방 ID | 방 멤버 권한 |
| LOT 클릭 | GET `/lots/:id/trace?direction=backward` | — | 계보 (LOT 추적 화면) | VIEW |
- 화면 요소 → 프론트 코드 (상호작용 정리에서 옮김)
    - 목록·필터: 필터 값은 URL 쿼리(`?status=` 등)에 두고, 쿼리 키 `salesOrderKeys.list(filters)`가 바뀌면 자동 재조회
    - 수주 등록 버튼: `router.push('/sales-orders/new')`, `usePermission('SALES_ORDER_CREATE', 'USE')`가 false면 숨김
    - 행 클릭: 오른쪽 미리보기 패널을 열고 `useSalesOrderDetail(id)`·`useFulfillment(id)` 호출
    - 상세 탭: URL `?tab=fulfillment|lots|events`, 탭은 처음 열 때만 조회
    - 출하요청 만들기: `/shipment-requests?salesOrderId=:id` (해당 품목 미리 체크)
    - 수정·취소 성공 시 `salesOrderKeys.detail(id)`·`salesOrderKeys.all` 무효화
    - 업무방 미리보기: `useRoomMessages(roomId)` + WebSocket `message:new` 수신 시 갱신

## 5. 상태 변화·작업 로그

- **수주 품목 상태** (저장값, 공통 코드 SALES_ORDER_ITEM_STATUS): OPEN → PARTIALLY_SHIPPED → SHIPPED, 취소 시 CANCELLED. 수주 헤더 상태는 저장하지 않고 품목 상태로 계산한다.
- **표시 상태**: 접수·예약 완료·생산 중·출하 대기·납기 위험은 충족 수치로 계산하는 표시값이며 저장하지 않는다.
- **취소 처리** (`SalesOrderCancellationService.cancel`, 한 트랜잭션):

```
1. 수주 품목·예약·배정 잠금
2. ACTIVE 예약 → RELEASED, inventory.reserved_qty 감소
3. CONFIRMED 배정 → RELEASED
4. PLANNED 생산계획 → CANCELLED
5. 진행 중 물량은 수주 연결을 끊고 "완료 후 여재" 표시
6. 작업 로그: SALES_ORDER_CANCELLED(USER), RESERVATION_RELEASED, ALLOCATION_RELEASED,
   PRODUCTION_PLAN_CANCELLED, SURPLUS_CONVERTED
```

- **수정**: 작업 로그 이벤트 유형(REQ-LOG-002)에 수주 수정이 없다. 남길지 결정 필요 🟡
