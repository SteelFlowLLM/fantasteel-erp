# 공정 실적

<aside>

근거: 요구사항 정의서 REQ-PRD-003·007, REQ-LOT-002·003, 업무 프로세스 정의서 BP-PRD-02·8장·9.2·12.2·16장, 공통코드 정의서, 역할별 메뉴 (v2)

－ 공정 실적은 제선·제강·연주 작업의 시작·완료와 실적을 등록해 LOT을 만드는 화면입니다. 시연용 실적 시뮬레이션도 여기서 실행합니다. MES 연동은 없습니다.

## 1. 목적·사용 역할·필요 권한

- 공정별 작업 시작·완료와 실적을 등록한다 (REQ-PRD-003).
- 생산계획을 골라 실적 시뮬레이션을 실행한다 (REQ-PRD-007).

| 역할 | 권한 `PRODUCTION_RESULT_CONFIRM` | 쓰는 방식 |
| --- | --- | --- |
| 생산 | 사용(USE) | 실적 등록, 시뮬레이션 실행 |
| 품질·관리자 | 조회(VIEW) | 실적 확인만 |

## 2. 철강 흐름에서의 위치

- 받는 것: 히트 편성이 확정된 생산계획, 원료·합금철 LOT(입고), 용선 LOT
- 넘기는 것: 용선 LOT → 제강 / 히트 LOT → 검사 입력(성분) / 슬래브 LOT → 검사 입력(표면·치수), 코일 계획이면 열연 투입

## 3. 화면에 표시할 데이터

| 공정 | 입력 | 처리·생성 LOT | LOT 연결 |
| --- | --- | --- | --- |
| 제선 IRONMAKING | 고로 코드(예: BF2), 작업일시, 원료 투입 기간, 용선량(t) | 원료별 투입량 = 용선량 × 원단위, 입고일 순(FIFO) 차감 → 용선 `HM-고로-YYMMDD-NN` | 원료 → 용선: 기간 기반 (PERIOD_BASED) |
| 제강 STEELMAKING | 전로 코드(예: BOF1), 히트 편성, 투입 용선량 | 용선 LOT FIFO 자동 투입, 합금철 = 히트 톤 × 원단위 ÷ 1,000 FIFO 차감 → 히트 `HT-전로-YYMMDD-NNN` | 용선 → 히트 N:M, 합금철 → 히트 (ACTUAL_INPUT) |
| 연주 CONTINUOUS_CASTING | 히트, 규격, 슬래브 매수, 작업일시 | 매별 슬래브 `히트번호-SS` | 히트 → 슬래브 1:N |
- 공통 표시: 계획번호, 공정(코드 PROCESS_TYPE), 작업 시작·완료 시각(한국 시간), 생성 LOT과 상태(코드 LOT_STATUS), 원료 LOT 차감 내역
- 고로·전로 코드는 채번용 식별값일 뿐, 설비 마스터는 만들지 않는다 (BP-PRD-02).

## 4. 사용자 동작 → API

| 동작 | 메서드·경로 | 요청 | 응답 | 권한·에러 |
| --- | --- | --- | --- | --- |
| 화면 진입 | `GET /api/v1/production-results` 🟡 | 필터: 계획·공정 | 실적 목록 | VIEW 이상. 없으면 COM-002 |
| 작업 시작 | 🟡 경로 미정 | 계획·공정·시작 시각 | 시작 기록 | USE |
| 실적 등록 (작업 완료) | `POST /api/v1/production-results` | 위 3장 공정별 입력 | 실적·생성 LOT | USE. 막을 것: 원료·용선 음수 잔량, 같은 실적 중복, 슬래브 번호 중복, 히트 생산량 초과 (에러 코드 미정) |
| 실적 시뮬레이션 | `POST /api/v1/production-plans/:id/simulate-results` | 계획 ID, 난수 시드 | 공정별 실적·LOT | USE |
- 시뮬레이션 규칙: 계획 수율 고정, 연주에서만 0~5% 손실(손실 매수 = floor(계획 매수 × 손실률)), 열연 수율 고정, 같은 시드면 같은 결과. 샘플 손실률과 실제 감소율을 함께 저장 (업무 프로세스 8장).

## 5. 상태 변화·작업 로그

- 작업에는 상태값이 없다. 실적의 시작·완료 시각으로 판단 (업무 프로세스 10장).
- 첫 실적 등록 → 생산계획 PLANNED → IN_PROGRESS
- 원료·용선 LOT 잔량 차감, 새 LOT은 AVAILABLE(재고), 모두 투입되면 CONSUMED
- 작업 로그: PRODUCTION_STARTED(작업 시작), PRODUCTION_RESULT_REGISTERED(실적 등록)
- 히트·슬래브가 생기면 품질에 검사 대기 알림 (검사 입력 페이지 6장)

## 6. 연결 화면·확인 필요

- 연결: 생산계획, 검사 입력, 열연 투입, LOT 추적, 작업 로그
- 확인 필요
    1. 🟡 API(실적 목록·작업 시작)를 API 명세서에 추가
    2. 실적 등록 에러 코드: 업무 프로세스 9.3에 생산 영역 코드가 없음
    3. 히트 판정 전 연주 진행 (16장 제안: 진행은 허용, 미합격 히트의 하위 제품은 예약·열연·출고 차단)
    4. 시뮬레이션이 검사도 자동 등록할지 기본값 (검사 입력 페이지 확인 필요 7번)
