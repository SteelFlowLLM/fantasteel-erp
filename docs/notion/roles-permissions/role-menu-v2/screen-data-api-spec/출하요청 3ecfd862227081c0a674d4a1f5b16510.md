## 1. 목적·사용 역할·필요 권한

- **목적**: 출하할 수주 품목과 매수를 요청하고, 시스템이 FIFO로 추천한 합격 LOT을 확인해 배정을 확정한다. 확정하면 물류가 출고할 수 있다 (REQ-SHP-001, REQ-INV-006).
- **사용 역할**: 영업. 물류·관리자는 조회만.
- **필요 권한**: `SHIPMENT_REQUEST_MANAGE` USE (등록·배정 확정·변경·취소), 밀시트 열람은 `MILL_SHEET_READ`

## 2. 철강 흐름에서의 위치

- **받는 것**: 수주 품목의 ACTIVE 예약, 검사 합격·미소진 제품 LOT(히트 성분 합격 + 제품 검사 합격), 생산완료일
- **넘기는 것**: ALLOCATED 출하요청과 CONFIRMED 배정(→ 물류 출고 확정 → 예약 CONVERTED·재고 소진 → 밀시트 발행)

## 5. 상태 변화·작업 로그

- **출하요청** (SHIPMENT_REQUEST_STATUS): REQUESTED(배정 대기) → ALLOCATED(배정 확정·출고 대기) → ISSUED(출고 완료), 출고 전 CANCELLED
- **배정** (ALLOCATION_STATUS): CONFIRMED → CONSUMED(출고 확정) 또는 RELEASED(변경·취소·해제)
- **추천**은 저장하지 않고 작업 로그로만 남긴다

**배정 확정 처리** (`AllocationService.confirm`, 한 트랜잭션)

```
1. 재고 풀·예약·LOT을 정해진 순서로 잠금 (SELECT ... FOR UPDATE)
2. 재검증: 강종·규격 일치, 히트 성분·제품 검사 합격, 미소진, 다른 CONFIRMED 배정 없음
3. allocation CONFIRMED 저장 — allocation(lot_id) 부분 unique 인덱스가 마지막 방어
4. 모든 품목이 확정되면 shipment_request → ALLOCATED
5. 작업 로그 ALLOCATION_CONFIRMED(USER), 물류 부서 알림
```

**작업 로그 이벤트**: SHIPMENT_REQUEST_CREATED, ALLOCATION_RECOMMENDED(SYSTEM), ALLOCATION_CONFIRMED, ALLOCATION_CHANGED, ALLOCATION_RELEASED. 이후 물류 출고 확정에서 GOODS_ISSUE_CONFIRMED, RESERVATION_CONVERTED, MILL_SHEET_ISSUED
