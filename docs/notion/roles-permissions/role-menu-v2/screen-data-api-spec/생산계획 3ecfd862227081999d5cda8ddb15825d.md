－ 생산계획은 수주의 부족 매수로 만들어진 계획을 보고, 히트를 편성해 확정하는 화면입니다. 불합격으로 매수가 모자라면 재생산 계획도 여기서 만듭니다.

## 1. 목적·사용 역할·필요 권한

- 수주 품목의 부족 매수로 생긴 생산계획을 확인한다 (REQ-PRD-001).
- 히트 편성: 미리보기로 히트 수를 계산하고 확정한다 (REQ-PRD-002).
- 합격 매수가 부족하면 부족 매수만큼 재생산 계획을 만든다 (REQ-PRD-006).

| 역할 | 권한 `PRODUCTION_PLAN_CONFIRM` | 쓰는 방식 |
| --- | --- | --- |
| 생산 | 사용(USE) | 편성·확정·취소·재생산 |
| 영업·구매·품질·관리자 | 조회(VIEW) | 계획·진행 확인만 (메뉴에는 생산만 보임) |

## 2. 철강 흐름에서의 위치

- 받는 것: 수주 등록 때 생긴 부족 매수 계획(PLANNED), 라우팅·수율·히트 용량(기준정보), 불합격 알림(검사 입력)
- 넘기는 것: 히트 편성 → MRP 원료 소요 → 구매요청 / 공정 실적(제선·제강·연주) / 코일 계획은 열연 투입

## 3. 화면에 표시할 데이터

| 영역 | 필드 | 타입·단위 | 출처 API |
| --- | --- | --- | --- |
| 목록 | 계획번호 `PP-YYMM-NNNN`, 수주번호·품목(강종·규격), 목표 매수, 납기, 상태 | 문자열 / 정수, 매 / 코드 PRODUCTION_PLAN_STATUS (계획·진행중·완료·취소) | `GET /api/v1/production-plans` 🟡 |
| 히트 편성 | 목표중량 = 부족 매수 × 1매 이론중량, 필요 용강 = 목표중량 ÷ 누적 계획수율, 히트 수 = ceil(필요 용강 ÷ 히트 용량), 히트 톤 | 톤(t) / 정수, 개. 히트 용량 초기 250t(설정값) | `POST /api/v1/production-plans/:id/heat-preview` |
| 히트 편성 | 예상 슬래브 여재 | 정수, 매 | 위와 같음 |
| MRP 요약 | 원료·합금철 총소요·순소요, 필요일 | 톤(t), 소수 3자리 | `GET /api/v1/mrp/requirements?from=&to=` |
| 진행 | 공정별 실적, 생성 LOT과 검사 판정 | LOT 번호 / 코드 INSPECTION_RESULT | `GET /api/v1/production-plans/:id` 🟡 |
- 수율은 두 번 적용하지 않는다: 히트 수는 연주·열연 수율로, 필요 용선은 제강 수율로 역산 (업무 프로세스 4.4).

## 4. 사용자 동작 → API

| 동작 | 메서드·경로 | 요청 | 응답 | 권한·에러 |
| --- | --- | --- | --- | --- |
| 화면 진입·상세 | `GET /api/v1/production-plans` 🟡, `GET /api/v1/production-plans/:id` 🟡 | 필터: 상태·수주 | 계획 목록 / 계획 상세 | VIEW 이상. 없으면 COM-002 |
| 히트 편성 미리보기 | `POST /api/v1/production-plans/:id/heat-preview` | 계획 ID | 히트 수·히트 톤·예상 여재 (저장 안 함) | USE. MST-001: 수율·배합·규격 매핑 누락 |
| 히트 편성 확정 | `POST /api/v1/production-plans/:id/confirm` | 계획 ID | 확정된 계획·히트 | USE. MST-001이면 확정 안 함 |
| MRP 보기 | `GET /api/v1/mrp/requirements?from=&to=` | 기간 | 원료별 소요 (저장 없이 계산) | PURCHASE_REQUISITION_CREATE (생산 보유) |
| 계획 취소 | `POST /api/v1/production-plans/:id/cancel` 🟡 | 사유 | CANCELLED | USE. PLANNED에서만 |
| 재생산 계획 생성 | 🟡 경로 미정 | 원래 수주 품목, 부족 매수 | 새 계획(PLANNED) | USE |

## 5. 상태 변화·작업 로그

- 상태: PLANNED → IN_PROGRESS(첫 실적 등록) → COMPLETED. CANCELLED는 PLANNED에서만 (업무 프로세스 10장, 공통코드 PRODUCTION_PLAN_STATUS).
- 완료 조건: 앞 공정 실적이 끝나고 판정 안 끝난 LOT이 없을 때, 코일 계획이면 열연까지 끝났을 때 (검사 입력 페이지 5장).
- 작업 로그: PRODUCTION_PLAN_CREATED, PRODUCTION_PLAN_CANCELLED, REPRODUCTION_PLAN_CREATED, SURPLUS_CONVERTED

## 6. 연결 화면·확인 필요

- 연결: 수주 상세, MRP·구매요청, 공정 실적, 열연 투입, 검사 입력(LOT 판정), LOT 추적, 작업 로그
- 확인 필요
    1. 🟡 API(목록·상세·취소·재생산)를 API 명세서에 추가
    2. MRP를 다시 계산해도 같은 계획의 구매요청을 중복 생성하지 않기. 구매요청 자동 초안은 P2, P1은 담당자가 직접 등록 (BP-PRD-01)
    3. 열연 시작 후 수주 취소 처리 (업무 프로세스 16장: 미열연은 슬래브 여재, 열연 후 코일은 별도 결정)
