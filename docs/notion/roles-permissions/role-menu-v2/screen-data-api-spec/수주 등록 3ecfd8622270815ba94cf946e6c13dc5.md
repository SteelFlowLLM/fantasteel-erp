## 1. 목적·사용 역할·필요 권한

- **목적**: 고객 주문을 규격 제품 **매수**로 등록한다. 저장하면 합격 재고를 먼저 예약하고, 모자란 매수만 생산계획으로 넘긴다 (REQ-SO-001·002·003, REQ-PRD-001).
- **사용 역할**: 영업
- **필요 권한**: `SALES_ORDER_CREATE` USE. 없으면 권한 없음 화면(42번)

## 2. 철강 흐름에서의 위치

- **받는 것**: 고객 주문(고객·납기·규격·매수), 기준정보(고객사, 슬래브·코일 규격과 1매 이론중량, 라우팅), 합격·가용 재고
- **넘기는 것**: ACTIVE 예약(→ 출하요청), 부족 매수의 생산계획(→ 생산팀 히트 편성·MRP), 업무방, 생산 부서 알림

## 4. 사용자 동작 → API

| 동작 | 메서드·경로 | 요청 | 응답 | 권한·에러 |
| --- | --- | --- | --- | --- |
| 화면 진입 (`useMe`) | GET `/auth/me` 🟡 | — | 로그인 사용자·권한 | 인증 |
| 고객 검색 (`useCustomerOptions`) | GET `/customers` 🟡 | 쿼리: keyword, active=true | id, 이름 | MASTER_MANAGE VIEW |
| 담당자 변경 | GET `/employees` | 쿼리: role=SALES | id, 이름, 부서 | 인증 |
| 구분·강종 선택 → 규격 목록 (`useItemOptions`) | GET `/items` | 쿼리: itemType, steelGradeId, active=true | itemId, 규격 코드, 치수, 1매 이론중량 | MASTER_MANAGE VIEW |
| 저장 (`useCreateSalesOrder`) | POST `/sales-orders` | 아래 요청 예시 | 아래 응답 예시 | SALES_ORDER_CREATE USE / SO-001 미등록 규격, SO-002 수량 오류, COM-002 권한 |
| 생산계획 내역 보기 | GET `/production-plans` 🟡 | 쿼리: salesOrderId | 생산계획 목록 | PRODUCTION_PLAN_CONFIRM VIEW |
| 저장 이벤트·작업 로그 전체 | GET `/business-events` | 쿼리: salesOrderId | 이벤트 목록 | VIEW |

## 5. 상태 변화·작업 로그

**저장 시 서버 처리** (`SalesOrderService.create`, 한 트랜잭션)

```
1. 수주번호 채번 SO-YYMM-NNN (Asia/Seoul)
2. sales_order, sales_order_item 저장 — 품목 상태 OPEN, 톤은 저장하지 않음
3. 품목마다 라우팅으로 생산 경로 결정
4. ReservationService.reserve(tx, item)
   - inventory 조건부 UPDATE: reserved_qty += n (가용 매수가 n 이상일 때만)
   - reservation ACTIVE 생성 (매수 단위, LOT 미지정)
5. 부족 매수가 있으면 ProductionPlanService.createForShortage → production_plan PLANNED
6. businessEventRecorder.record(tx, ...)
   SALES_ORDER_REGISTERED(USER), RESERVATION_CREATED(SYSTEM), PRODUCTION_PLAN_CREATED(SYSTEM)
7. 업무방(chat_room WORK) 생성, 생산 부서 알림 🟡
```

- 가용 매수 = 미소진 합격 제품 매수 − ACTIVE 예약 매수 − 예약으로 덮이지 않은 열연용 CONFIRMED 배정 매수 (업무 프로세스 4.2)
- 예약이 부족해도 오류가 아니다. 모자란 매수는 생산계획으로 넘어간다.
