# 6. 팀장

데모 계정: **강팀장** (`1502003`) · 시작 화면: 팀장 대시보드

## 하는 일

- **구매요청을 승인·반려**합니다. 승인은 팀장만 할 수 있고, 자동 조업도 대신하지 않습니다.
- **AI Factory Agent**가 감지한 문제와 대응 후보를 보고 승인·반려합니다.
- 과거 사례를 검색해 판단에 참고합니다.
- 그 밖의 업무 화면은 대부분 조회만 됩니다. 예외로 구매요청 등록, 불합격 상태 변경은 직접 할 수 있습니다.

## 쓰는 메뉴

- 대시보드 / 승인함 / AI Factory Agent / 과거 사례 검색

## 따라 하기

### A. 구매요청 승인

1. "승인 요청 · PR-…" 알림이 오면 **승인함**을 엽니다.
2. **구매요청** 탭에서 원료, 수량, 요청자, 근거를 확인합니다.
3. **승인**, **반려**, **보류** 중에서 고릅니다.
    - 승인: 구매팀에 "발주 가능" 알림이 갑니다.
    - 반려: 사유를 적고 **반려 확정**을 누릅니다. 요청자에게 사유와 함께 알림이 갑니다.
4. 처리한 건은 **처리 완료** 탭에 모입니다.

### B. AI Agent 대응

1. Agent는 매시 정각(공장 시각)에 네 가지를 감지합니다: **원료 부족, 납기 위험, 여재 장기 보유, 불합격률 상승**.
2. **AI Factory Agent** 화면에서 감지 내용과 근거를 봅니다.
3. 대응 후보가 붙어 있으면 **승인함 → Agent 대응 후보** 탭에서 하나씩 승인·반려합니다. 후보 종류는 다음과 같습니다.
    - 히트 시작 앞당김 (납기 위험)
    - 구매요청 초안 (원료 부족): 승인하면 승인된 구매요청이 바로 만들어져 구매팀이 발주할 수 있습니다.
    - 재생산 계획 초안
4. AI는 상황 설명과 초안까지만 합니다. **실행은 승인해야 일어납니다.**

### C. 과거 사례 검색

1. **과거 사례 검색**에 키워드(예: "인장강도 불합격")를 넣고 **검색**합니다.
2. 작업 로그에서 비슷한 사건을 찾아 요약해 줍니다. 실패하면 **다시 시도**를 누릅니다.

### D. 그 밖에

- 팀원의 업무(업무·알림) 상태를 바꿀 수 있습니다.
- **작업 로그**에서 누가 언제 무엇을 했는지, 자동 조업이 무엇을 대신했는지 볼 수 있습니다.

## 자주 생기는 문제

- **"본인이 요청한 건은 승인할 수 없어요"**: 팀장이 직접 올린 구매요청은 스스로 승인할 수 없습니다. 팀장 계정이 하나뿐이라 이 프로토타입에서는 그대로 막힙니다. 구매·생산 담당이 요청을 올리게 합니다.
- **"승인 대기 상태의 요청만 승인할 수 있어요"**: 아직 요청자가 확정하지 않은 초안이거나 이미 처리된 건입니다. 초안이면 요청자에게 확정을 부탁합니다.
- **"이미 처리된 후보예요"**: 다른 창에서 이미 승인·반려했습니다.
- **"이미 시작된 히트는 일정을 바꿀 수 없어요"**: 앞당김 후보를 승인하려 했지만 그 히트가 이미 제강에 들어갔습니다. 반려하고 다른 대응을 찾습니다.
- **승인 대기가 계속 쌓인다**: 자동 조업은 승인을 대신하지 않으므로 팀장이 처리하지 않으면 발주가 멈춥니다.
- **Agent 감지가 안 뜬다**: 시계가 일시정지 상태인지 확인합니다. +1h로 다음 정각을 넘기면 감지가 돕니다.
