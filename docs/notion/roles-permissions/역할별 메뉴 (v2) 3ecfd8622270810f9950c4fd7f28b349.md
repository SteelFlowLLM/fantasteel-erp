## 5. 결정 (2026-10-01)

- 역할은 6개로 확정 (요구사항 REQ-AUTH-003, 용어 사전 TRM-037 반영)
- 승인은 부서장 지정으로만 판단. 승인 권한 코드는 두지 않음 (REQ-AUTH-004)
- ROLE·PERMISSION_LEVEL·PERMISSION을 공통코드 정의서에 등록
- 권한 코드 이름은 용어 사전 영문명 + `{대상}_{동작}` 형식으로 통일 (코드 컨벤션 2장의 `order` 단독 사용 금지 포함). v2 코드의 `shared/src/codes/index.ts`, `nav.ts` 수정 필요

## 6. 기준 문서 6개 반영 (2026-10-02)

- 생산의 PURCHASE_REQUISITION_CREATE를 사용 → 조회로 변경, MRP·구매요청 메뉴는 구매만. 근거: 업무 프로세스 정의서 2장(생산 권한), BP-PRD-01·BP-PUR-01 주체, 기획안 주요 사용자(구매 = MRP 결과 확인·구매요청)
- MILL_SHEET_READ 사용은 물류만, 영업·품질은 조회. 밀시트 메뉴는 물류만. 근거: 업무 프로세스 정의서 2장, 공통코드 PERMISSION(영역 물류), 기획안 주요 사용자
- 품질 메뉴에 “검사 기준” 추가. 근거: REQ-QC-002, INSPECTION_STANDARD_MANAGE
- “공정 실적” → “작업 실적”. 근거: 용어 사전 TRM-047(사용 금지 동의어)
- 대시보드에 P3 표시. 근거: 요구사항 18장
- 1장 “하는 일”을 업무 프로세스 정의서 2장·기획안 주요 사용자에 맞춤
- 후속 필요: `nav.ts`·`DEFAULT_ROLE_PERMISSIONS` 반영, 공통코드 정의서 PERMISSION 표시명 “공정 실적(…)”을 용어 사전에 맞게 수정, 하위 “화면별 데이터·API 명세”는 이번에 수정하지 않음
