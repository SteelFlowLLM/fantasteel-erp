- `[강제]` 용어 사전의 동의어(사용 금지) 칸에 있는 단어는 코드에 쓰지 않는다. `order` 단독 사용 금지 → `salesOrder` / `purchaseOrder`
- `[강제]` 단위를 이름에 포함: 매수는 `Qty`, 톤은 `Ton` (`reservedQty`, `theoreticalWeightTon`, `requiredTon`)
- `[강제]` 제품(슬래브·코일) 수주·재고의 톤은 저장하지 않고 매수 × 1매 이론중량으로 계산한다(REQ-SO-002, REQ-INV-001). 제품 테이블에 톤 합계 컬럼을 만들지 않는다
- `[권장]` Boolean은 `is`/`has` 접두사, 날짜는 `Date`, 시각은 `At` 접미사 (`isPassed`, `dueDate`, `confirmedAt`)

## 3. Supabase 사용 규칙

- `[강제]` 업무 데이터(`public` 스키마)는 NestJS API로만 읽고 쓴다. 프론트에서 supabase-js로 업무 테이블에 직접 접근하지 않는다. 권한 검증, 작업 로그, AI 안전 규칙이 서버에 있기 때문이다(REQ-AUTH-003, REQ-LOG-001, REQ-AST-004)
- `[강제]` `SUPABASE_SERVICE_ROLE_KEY`와 DB 접속 문자열은 서버에서만 쓴다. `VITE_` 변수로 노출하지 않는다
- `[강제]` 스키마는 Prisma Migrate로만 바꾼다. Supabase 대시보드 Table Editor, `supabase db diff`, `supabase/migrations`로 스키마를 바꾸지 않는다. Prisma는 `public` 스키마만 관리하고 `auth`·`storage` 등 Supabase 관리 스키마는 건드리지 않는다
- 로컬 개발: Docker 실행 후 `supabase start`로 로컬 스택을 띄운다. 로컬 DB는 `localhost:54322`, Studio는 `localhost:54323`
- Supabase 기능 사용 범위

| 기능 | 결정 | 관련 요구사항 |
| --- | --- | --- |
| Auth | 사용 안 함. NestJS 자체 JWT로 사원번호·비밀번호 로그인 (6장) | REQ-AUTH-001 |
| Storage | 메시지 첨부·밀시트 PDF 저장에 사용. 업로드와 서명 URL 발급은 서버에서 | REQ-MSG-003, REQ-SHP-004 |
| Realtime | 사용 안 함. NestJS WebSocket Gateway로 메신저 실시간 송수신 | REQ-MSG-002 |

## 4. 공통코드

- 코드 그룹·값 모두 영문 대문자 의미어. 숫자 코드(`01`, `02`) 금지
- `[강제]` 요구사항에 정의된 상태값은 그대로 쓴다

| 코드 그룹 | 값 | 근거 |
| --- | --- | --- |
| UNIT_TYPE | QTY, TON | REQ-MST-001 |
| RESERVATION_STATUS | ACTIVE, CONVERTED, RELEASED | REQ-INV-002 |
| ALLOCATION_STATUS | CONFIRMED, CONSUMED, RELEASED | REQ-INV-006 |
| DRAFT_STATUS | AI_GENERATED, WAITING_APPROVAL, APPROVED, EXECUTED, REJECTED | REQ-ACT-003 |
| ACTOR_TYPE | USER, SYSTEM | REQ-LOG-001 |

- 예약 상태와 배정 상태는 **별도 그룹**
- 요구사항에 값이 없는 코드(수주 상태, 불합격 처리 상태 등)는 공통코드 정의서에서 확정한 뒤 쓴다
- `[강제]` 상태값은 `shared/`에 값·타입·한글 표시명을 한 번만 정의하고 server·client가 import한다. DB 컨럼은 String이며 Prisma enum은 쓰지 않는다
- `[강제]` 서버는 DTO에서 `@IsIn(Object.values(RESERVATION_STATUS))`처럼 검증하고, 상태 변경은 service에서만 한다
- 공통코드 테이블·API는 만들지 않는다. 관리자가 직접 바꿔야 하는 표시용 분류가 생기면 그 코드에만 추가한다
- `[권장]` 핵심 상태 컨럼(예약·배정·초안)은 마이그레이션에 CHECK 제약을 추가한다

export const RESERVATION_STATUS = {

  RELEASED: 'RELEASED',
} as const;
export type ReservationStatus =
  typeof RESERVATION_STATUS[keyof typeof RESERVATION_STATUS];

export const RESERVATION_STATUS_LABEL: Record<ReservationStatus, string> = {
  ACTIVE: '예약중',

## 5. API

- `[강제]` 경로는 `/api/v1` + kebab-case 복수 명사. 상태 변경은 액션 URL `POST /:id/동작` (예: `POST /api/v1/goods-issues/:id/confirm`)
- `[강제]` 응답 포맷. 성공 응답은 전역 인터셉터, 실패 응답은 전역 예외 필터에서 만든다

```typescript
{ success: true, data: {...} }
{ success: false, error: { code: 'SO-002', message: '수량은 1 이상의 정수로 입력해 주세요' } }
```

- `[강제]` 에러는 `AppException(code, message, httpStatus)`을 throw한다. 컨트롤러별 try/catch 응답 금지
- `[강제]` 에러 코드는 `영역-번호`. 영역은 요구사항 영역 코드를 쓴다 (`SO-001`, `INV-003`, `PUR-002`). 공통 에러는 `COM-`
- `[강제]` 요청 검증은 class-validator 데코레이터를 붙인 DTO + 전역 ValidationPipe(`whitelist`, `forbidNonWhitelisted`, `transform` 활성화)
- `[강제]` 톤 등 Decimal 값은 응답에서 문자열로 변환한다
- 페이징 `page`, `size`, `sort` / 날짜 ISO 8601 / 🟡 타임존 (DB는 timestamptz 저장, 화면은 Asia/Seoul 표시 권장)

## 6. 레이어 (NestJS)

| 레이어 | 역할 |
| --- | --- |
| module | 의존성 조립 |
| controller | 라우팅, DTO 검증, 가드 적용. 업무 로직 금지 |
| service | 업무 로직, 트랜잭션, 데이터에 따른 권한 검사 |
| repository | DB 접근 (유일) |

- `[강제]` 트랜잭션은 service에서 `this.prisma.$transaction(async (tx) => ...)` — 수주 등록, 예약, 배정, 출고 확정, 입고 확정
- `[강제]` 예약 생성·전환·해제와 `reserved_qty` 갱신은 같은 트랜잭션에서 한다(REQ-INV-009)
- `[강제]` 권한: 컨트롤러에 인증 가드와 역할 가드(`@Roles()`)를 적용한다. 승인권자(부서장) 여부처럼 데이터에 따라 달라지는 권한은 service에서 검사한다(REQ-AUTH-004)
- `[강제]` 로그인은 사원번호·비밀번호. 비밀번호는 bcrypt 해시로 저장하고 평문 저장·로그 출력 금지
- `[강제]` 인증은 `@nestjs/jwt`로 발급한 access token을 인증 가드에서 검증한다. 토큰 만료·갱신 방식은 비기능 요구사항 결정 후 정한다
- `[강제]` 메신저 실시간 송수신은 messenger 모듈의 WebSocket Gateway로 하고, 연결 시에도 access token을 검증한다
- `[강제]` 작업 로그는 본 거래와 같은 트랜잭션에서 저장한다(REQ-LOG-001)
- 🟡 작업 로그 기록 방식: service에서 직접 호출 vs `@nestjs/event-emitter`
- 🟡 Prisma 모델을 그대로 응답할지, 응답 DTO로 변환할지

### 7-1. 연결 (Prisma 7 + Supabase)

| 환경변수 | 용도 | 원격 Supabase | 로컬 |
| --- | --- | --- | --- |
| `DATABASE_URL` | 앱 실행(Prisma Client) | Transaction pooler(6543) + `?pgbouncer=true` | `localhost:54322` |
| `DIRECT_URL` | Prisma CLI (`migrate`, `generate --sql`) | Direct 연결 또는 Session pooler(5432) | `localhost:54322` |

```typescript
// server/prisma.config.ts — Prisma CLI는 직접 연결 사용
import 'dotenv/config';
import { defineConfig, env } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: { path: 'prisma/migrations', seed: 'tsx prisma/seed.ts' },
  datasource: { url: env('DIRECT_URL') },
});
```

```javascript
// server/prisma/schema.prisma
generator client {
  provider        = "prisma-client"
  output          = "../src/generated/prisma"
  previewFeatures = ["typedSql"]
}

datasource db {
  provider = "postgresql"
}
```

```typescript
// server/src/prisma/prisma.service.ts — 앱은 풀러 URL + 드라이버 어댑터
import { Injectable, OnModuleInit, OnModuleDestroy } from '@nestjs/common';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../generated/prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor() {
    super({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) });
  }
  async onModuleInit() { await this.$connect(); }
  async onModuleDestroy() { await this.$disconnect(); }
}
```

- `[강제]` PrismaService는 전역 PrismaModule 하나로만 제공한다. `new PrismaClient()`를 다른 곳에서 만들지 않는다
- `[강제]` 마이그레이션·`generate --sql`을 풀러(6543) URL로 실행하지 않는다

### 7-2. 스키마

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 모델명 | PascalCase 단수 | `Reservation` |
| 테이블명 | `@@map` snake_case 단수 (용어 사전 DB명) | `@@map("reservation")` |
| 필드명 / 컬럼명 | camelCase / `@map` snake_case | `reservedQty @map("reserved_qty")` |
| FK 필드 | `{관계명}Id` | `salesOrderItemId` |
| 관계 필드 | 단수 = 모델명, 복수 = 복수형 | `salesOrderItem`, `reservations` |

```javascript
model Reservation {
  id               Int               @id @default(autoincrement())
  salesOrderItemId Int               @map("sales_order_item_id")
  productSpecId    Int               @map("product_spec_id")
  reservedQty      Int               @map("reserved_qty")
  status           String            @default("ACTIVE") // RESERVATION_STATUS (shared)
  createdAt        DateTime          @default(now()) @map("created_at")
  updatedAt        DateTime          @updatedAt @map("updated_at")

  salesOrderItem SalesOrderItem @relation(fields: [salesOrderItemId], references: [id])
  productSpec    ProductSpec    @relation(fields: [productSpecId], references: [id])

  @@index([salesOrderItemId])
  @@map("reservation")
}
```

- `[강제]` `@map` / `@@map` 누락 금지
- `[강제]` 모든 모델에 `createdAt`, `updatedAt`
- `[강제]` 톤 등 소수값은 `Decimal` (`@db.Decimal(12, 3)`), `Float` 금지
- `[강제]` 매수(qty)는 `Int`
- `[강제]` 업무번호(LOT 번호, 수주번호 등)는 PK와 별도 `@unique` 컬럼
- `[강제]` 제품 규격은 강종·두께·폭·길이 조합에 `@@unique`를 건다. 사용된 규격의 치수·이론중량 수정은 service에서 막는다(REQ-MST-003)
- 🟡 삭제 방식: 수주·LOT·출하는 소프트 삭제(`deletedAt`), 예약은 물리 삭제 (안)

### 7-3. 마이그레이션

- `[강제]` 공유 반영은 로컬 Supabase에 `prisma migrate dev`로만 한다. `db push`는 개인 로컬 실험용

- 🟡 충돌 방지: 스키마 담당자 1명 vs 머지 전 rebase 후 재생성

## 8. 쿼리 관리

| 쿼리 유형 | 작성 방법 | 위치 |
| --- | --- | --- |
| 단건 조회·등록·수정·삭제 | Prisma Client | `{도메인}.repository.ts` |
| 조건 검색(동적 필터·페이징) | Prisma Client (`where` 조건부 조립) | `{도메인}.repository.ts` |
| 복잡한 쿼리 | TypedSQL | `prisma/sql/{동사}{대상}.sql` |

**복잡한 쿼리 기준** (하나라도 해당)

- 집계(GROUP BY, 윈도우 함수) — MRP 순소요, 수주 충족 현황, 대시보드 통계
- 3개 이상 테이블 JOIN 또는 서브쿼리 — LOT 정·역추적
- 락 필요 (`SELECT ... FOR UPDATE`) — 재고 풀 잠금
- Prisma Client로 표현 불가하거나 N+1 발생
- 애매하면 PR 리뷰어가 판단

**규칙**

- `[강제]` DB 접근은 repository에서만. service·controller에서 PrismaService 직접 쿼리 금지 (트랜잭션 시작만 예외)
- `[강제]` `$queryRaw` 인라인 SQL 금지, `$queryRawUnsafe` 금지
- `[강제]` repository 함수 첫 인자는 `tx`
- SQL 파일명은 camelCase 동사구 (`getReservedQtyBySpec.sql`), 상단에 목적 주석 한 줄
- 파라미터는 `-- @param {타입} $1:이름`으로 명시
- 스키마 변경 시 `migrate dev` → `generate --sql` 실행 (로컬 Supabase가 떠 있어야 함)
- `[권장]` `select` / `include` 명시
- 🟡 동시성 처리: 조건부 update vs `FOR UPDATE` (TypedSQL)

```sql
-- prisma/sql/getReservedQtyBySpec.sql
-- 수주별 규격 예약 매수 합계(ACTIVE)
-- @param {Int} $1:salesOrderId
SELECT r.product_spec_id, SUM(r.reserved_qty) AS reserved
FROM reservation r
JOIN sales_order_item i ON i.id = r.sales_order_item_id
WHERE i.sales_order_id = $1
  AND r.status = 'ACTIVE'
GROUP BY r.product_spec_id;
```

```typescript
// inventory.repository.ts
import { Prisma } from '../../generated/prisma/client';
import { getReservedQtyBySpec } from '../../generated/prisma/sql';

export const findReservedQtyBySpec = (tx: Prisma.TransactionClient, salesOrderId: number) =>
  tx.$queryRawTyped(getReservedQtyBySpec(salesOrderId));
```
