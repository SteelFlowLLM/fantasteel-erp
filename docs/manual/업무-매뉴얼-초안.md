# 업무 매뉴얼 초안 (화면 절차)

> 상태: **초안 · 팀 검수 전.** 화면 코드(`client/src/features/`)를 읽고 썼다. 실제 화면과 다른 곳이 있으면 고친다.
> 범위: 추천 질문에 나온 업무 4개 — 수주 등록, 구매요청 등록, 검사 입력(검사 등록), 출고 확정. 나머지 업무는 검수 담당·개수가 정해진 뒤에 늘린다([02] 21장).
> 근거 약어: [04] 업무 프로세스 정의서. 각 업무 끝의 '근거 파일'은 검수할 때 화면과 맞춰 볼 파일이다.
> 🟡 = 코드만으로 확정하기 어려워 검수에서 확인할 곳.

이 매뉴얼은 "어디를 눌러 하는지"만 적는다. 업무의 순서·정상 흐름은 [04]에 있고, AI 어시스턴트는 그 표로 답한다.

## 1. 수주 등록 (BP-SO-01)

| 항목 | 내용 |
| --- | --- |
| 하는 사람 | 영업 (수주 등록 **사용** 권한) |
| 여는 곳 | 왼쪽 메뉴 **수주 → 등록** (`/sales-orders/new`) |
| 권한이 없으면 | 조회만 되는 역할은 화면은 열려도 **저장** 버튼이 잠기고 "필요한 권한" 안내가 떠요 |

**절차**

1. **1 기본 정보**에서 **고객사**를 고른다. 담당은 등록하는 사원이 자동으로 들어가고 바꿀 수 없다.
2. **2 품목**에서 첫 줄을 채운다.
   1. 품목 유형(슬래브·코일)과 강종을 고른다. 강종은 "강종 전체"로 두어도 된다.
   2. **규격**을 고른다. 등록된 규격만 나온다. 목록이 비어 있으면 "등록된 규격이 없어요"가 보인다.
   3. **매수**를 정수로 입력한다 (슬래브는 매, 코일은 개). 소수·0·글자는 받지 않고, 톤은 매수 × 1매 이론중량으로 자동 계산해서 보여 준다 (저장하지 않는다).
   4. **납기**를 날짜로 입력한다. 납기는 품목마다 따로 정한다.
3. 품목이 더 있으면 **품목 행 추가**를 누르고 같은 방식으로 채운다. 줄은 휴지통 아이콘으로 뺀다 (줄이 하나뿐이면 못 뺀다). 슬래브와 코일을 섞어도 된다.
4. 오른쪽의 **품목별 예약 미리보기**로 확인한다. 예약 가용·예약할 매수·부족 매수와, 부족하면 생산계획의 히트 편성(히트 수·히트 톤·필요 용강량·예상 여재)이 보인다. 미리보기는 지금 재고 기준이고, 저장하는 순간의 재고로 다시 계산한다.
5. 아래의 **저장**을 누른다. 빠진 칸이 있으면 해당 칸에 빨간 안내가 뜨고 저장되지 않는다.

**저장하면**

- 수주 번호(SO-YYMM-NNN)가 매겨지고 품목별 납기와 함께 저장된다.
- 합격한 가용재고를 매수 단위로 먼저 예약한다 (부분 예약 허용). 이 예약은 시스템이 한다.
- 부족한 매수만 생산계획이 만들어진다 (슬래브는 제선→제강→연주, 코일은 열연까지).
- 작업 로그에 수주 등록·예약·생산계획 생성이 남고, 수주 상세 화면으로 넘어간다. 알림 문구로 예약 매수와 만들어진 생산계획 건수가 나온다.

**자주 막히는 곳**

| 보이는 것 | 뜻 | 할 일 |
| --- | --- | --- |
| 매수 칸에 SO-002 문구 | 1 이상의 정수가 아니에요 | 정수로 다시 입력 |
| "규격을 선택해 주세요" | 규격이 비어 있어요 | 규격 선택 |
| "납기를 입력해 주세요" | 납기가 비어 있어요 | 납기 입력 |
| 납기 칸에 서버 오류 | 서버가 납기를 받지 않았어요 | 안내 문구대로 날짜 수정 🟡 문구 종류는 서버 검증에 따라 다름 |

근거 파일: `features/sales/SalesOrderCreateScreen.tsx`, `features/sales/lib/salesOrderForm.ts`

## 2. 구매요청 등록 (BP-PUR-01)

| 항목 | 내용 |
| --- | --- |
| 하는 사람 | 구매 (구매요청 등록·MRP **사용** 권한) |
| 여는 곳 | 왼쪽 메뉴 **구매요청** (`/purchase-requisitions`) → 왼쪽 위 **구매요청 등록** |
| 다른 길 | MRP 화면의 순소요를 보고 등록하면 원료·수량·근거 생산계획이 미리 채워져요. 메신저 메시지에서 초안을 만들어 확정하는 길도 있어요 |

**절차**

1. **구매요청 등록**을 누르면 창이 열린다. 창 아래쪽에 승인을 받을 부서장 이름이 보인다.
2. **원료 품목 · 수량(톤)**: 원료를 고르고 수량을 톤으로 입력한다 (소수 3자리까지). 구매요청 1건에 원료는 1품목이라 원료가 여러 개면 요청을 따로 만든다. 원료를 고르면 기본 공급업체와 기본 야드가 아래에 보인다.
3. **희망 입고일**을 입력한다. 발주할 때 납기의 기본값이 된다.
4. **요청 근거**에 어디에 쓰는지, 왜 필요한지 적는다 (선택, 500자까지).
5. **등록**을 누른다. 요청자와 부서는 자동으로 들어간다.

**등록하면**

- 임시 저장 없이 바로 **승인 대기**가 되고, 요청자 소속 부서의 부서장에게 승인 요청이 간다.
- 같은 화면에서 새 요청이 선택되어 오른쪽에 진행 단계(등록 → 부서장 승인 → 발주)가 보인다.

**등록할 수 없는 경우**

| 보이는 것 | 뜻 | 할 일 |
| --- | --- | --- |
| "소속 부서에 승인권자(부서장)가 지정되지 않아…" (PUR-001) | 부서장이 없어요 | 관리자에게 부서장 지정을 요청 |
| "부서장 본인 요청은 승인할 사람이 없어…" (PUR-001) | 부서장 본인은 요청할 수 없어요 (자동 승인 금지) | 부서원이 요청하고 부서장이 승인함에서 승인 |
| 등록 버튼이 잠김 | 사용 권한이 없어요 | 마우스를 올리면 필요한 권한이 보여요 |

**이어지는 일** (같은 업무의 다음 화면)

- **승인·반려**: 요청 부서의 부서장이 **승인함**(부서장에게만 보이는 메뉴) 또는 구매요청 상세의 **처리** 카드에서 한다. 반려할 때는 사유가 필수고 요청자에게 전달된다.
- **반려된 요청**: 요청자가 구매요청 상세의 **고쳐 다시 요청**을 눌러 수량·희망 입고일·요청 근거를 고친다 (원료는 못 바꾼다. 다른 원료는 새 요청). 다시 요청하면 바로 승인 대기가 된다.
- **발주**: 승인된 요청은 상세 화면에서 **발주 만들기**(발주 확정 권한)로 발주 화면에 넘어간다.

근거 파일: `features/purchasing/RequisitionListScreen.tsx`, `features/purchasing/components/RequisitionFormModal.tsx`, `features/purchasing/components/RequisitionPanel.tsx`, `features/purchasing/ApprovalScreen.tsx`

## 3. 검사 입력 — 검사 등록 (BP-QC-01)

| 항목 | 내용 |
| --- | --- |
| 하는 사람 | 품질 (검사 입력 **사용** 권한) |
| 여는 곳 | 왼쪽 메뉴 **검사 입력** (`/quality/inspections`). LOT을 고르면 주소에 `?lot=`이 붙어요 |
| 화면 이름 | 메뉴·화면은 "검사 입력", 작업 로그의 이벤트 이름은 "검사 등록·판정" |

**절차**

1. 왼쪽 **검사 대상 LOT** 목록에서 LOT을 고른다. 처음에는 **판정 대기**만 보이고, 생산완료일 순이다.
   - 위쪽 탭으로 공정(전체·제강·연주·열연)을, 칩으로 판정 결과(전체·합격·불합격·판정 대기)를 바꾼다. 탭의 숫자는 판정 대기 수다.
   - 돋보기를 누르면 LOT 번호로 찾는다.
2. 오른쪽 위에서 LOT 정보(강종·규격, 적용된 검사 기준 버전, 상위 히트의 성분 검사 결과, 생산계획, 수주)를 확인한다.
3. **측정값** 카드에서 항목마다 측정값을 입력한다.
   - `*` 표시는 필수 항목, "선택"은 비워도 되는 항목이다.
   - 입력하는 동안 칸 옆 배지의 합격·불합격은 기준과 견준 **미리보기**다. 판정은 저장할 때 시스템이 한다. 소수 4자리까지 숫자만 받는다.
   - Enter를 누르면 저장이 아니라 **다음 칸**으로 간다. 마지막 칸에서 Enter를 누르면 저장 버튼으로 간다.
4. 아래 저장 줄의 문구를 확인한다.
   - "모든 필수 항목이 기준 안이에요" → 저장하면 **합격**
   - "기준 밖 N개" → 저장하면 **불합격**
   - "필수 항목이 비어 있어요" → 저장하면 **판정 대기**로 남는다
5. **검사 등록**을 누른다. 이미 값이 있는 LOT이면 버튼 이름이 **측정값 수정**이고, 바꾼 항목만 저장하며 **되돌리기**로 저장 전 값으로 돌릴 수 있다.

**저장하면**

- 위쪽에 **시스템 판정** 카드가 뜨고, 같은 저장에서 일어난 일(자동 예약, 여재 처리, 예약·배정에서 제외, 수주 품목의 부족 등)이 줄로 나온다.
- 불합격이면 **불합격 관리에서 상태 지정** 버튼이 뜬다. 거기서 처리 상태를 정한다.
- **다음 판정 대기 LOT** 버튼으로 바로 다음 LOT으로 넘어간다.
- 값을 고친 경우 바꾼 값의 전·후가 작업 로그에 남는다.

**막히거나 잠기는 경우**

| 보이는 것 | 뜻 | 할 일 |
| --- | --- | --- |
| "검사 기준이 없어 판정할 수 없어요" (MST-001) | 이 공정·강종에 검사 기준이 없어요 | 품질 담당이 **검사 기준** 화면에서 기준 등록 |
| "이 LOT에 적용할 검사 항목이 없어요" | 기준에 이 LOT에 맞는 항목이 없어요 | 검사 기준 화면에서 항목 확인 |
| 자물쇠 + "밀시트 발행 · 수정 불가" | 이미 밀시트가 발행돼 측정값을 고칠 수 없어요 | 수정할 수 없음 |
| "상위 히트 … 판정 대기예요" | 슬래브·코일은 먼저 검사할 수 있지만 히트가 합격해야 예약·배정할 수 있어요 | 히트(제강) LOT을 먼저 판정 |
| "상위 히트 … 성분 불합격" | 이 LOT이 합격해도 예약·배정·출고할 수 없어요 | 불합격 관리에서 처리 |
| 입력 칸과 저장 버튼이 잠김 | 사용 권한이 없거나 위의 잠금 사유예요 | |

> 🟡 **기준 안 값으로 채우기**(점선 버튼, "시연용 도우미")는 시연용이다. 실제 업무 절차로 안내하지 않는다.

근거 파일: `features/quality/components/InspectionWorkspace.tsx`, `features/quality/components/InspectionForm.tsx`, `features/quality/lib/inspectionOutcomeNotes.ts`

## 4. 출고 확정 (BP-SHP-01)

| 항목 | 내용 |
| --- | --- |
| 하는 사람 | 물류 (출고 확정 **사용** 권한) |
| 전제 | 영업이 출하요청의 **배정을 모두 확정**해야 목록에 올라와요 |
| 여는 곳 | 왼쪽 메뉴 **출고 확정** (`/goods-issues`). 출하요청 화면에서 `?request=`로 바로 올 수도 있어요 |

**절차**

1. 왼쪽 목록의 상태 칩에서 **배정 확정**(처음 선택), 배정 대기, 출고 완료를 바꿔 볼 수 있다. 출하요청 번호·고객사로 검색할 수 있다.
2. 출고할 출하요청을 고른다. 목록에 **출고 불가 N건**이 붙어 있으면 아래 막힘을 먼저 푼다.
3. 오른쪽 **배정 LOT 출고 확인**에서 LOT마다 제품 검사·상위 히트 검사·재고 상태를 확인한다.
4. **출고 전 확인** 카드의 세 줄이 모두 초록인지 본다.
   - 배정 확정 (확정된 LOT 수 / 요청 매수)
   - 검사 합격 (제품 + 상위 히트)
   - 미소진 (재고)
5. **확정하면 바뀌는 것** 카드로 효과를 확인한다.
6. **출고 확정**을 누른다. 두 번 눌러도 한 번만 출고된다. 확정은 **출하요청 단위**고, 부분 출하는 출하요청을 나눠서 한다.

**확정하면**

- 배정은 소진, LOT은 출고 상태가 된다.
- 예약은 출고 전환이 된다. 일부만 출고하면 예약을 나눠 남은 매수는 예약중으로 둔다.
- 수주 품목의 출고 매수가 늘고 품목 상태가 부분출하·출하완료로 바뀐다.
- 밀시트가 수주마다 1장씩 자동 발행된다. **밀시트 보기** 버튼으로 이동한다.
- 작업 로그에 출고 확정·예약 전환·밀시트 발행이 남는다. 화면에는 **출고 결과** 카드가 나온다.

**막히는 경우** — 서버가 품질·배정·재고·잔량을 다시 확인하고, 하나라도 맞지 않으면 **아무것도 출고되지 않는다.**

| 코드 | 뜻 | 할 일 |
| --- | --- | --- |
| INV-002 | 미검사·불합격(제품 또는 상위 히트) LOT이 배정돼 있어요 | 출하요청·배정 화면에서 합격 LOT으로 바꾸기 |
| SHP-002 | 요청 매수가 예약·수주 잔량을 넘어요 | 배정 화면에서 출하요청을 취소하고 매수를 줄여 다시 요청 |
| INV-004 | 이미 투입·출고된 LOT이 배정돼 있어요 | 다른 LOT으로 바꾸기 |
| INV-001 | 배정 대기 매수가 남아 있어요 | 영업이 배정을 모두 확정 |
| COM-001 | 다른 화면에서 이미 출고했거나 출하요청이 바뀌었어요 | 목록을 다시 확인 |

그 밖에: 배정 대기·취소된 출하요청은 확정 버튼이 잠기고, 사용 권한이 없어도 잠긴다 (마우스를 올리면 필요한 권한이 보인다). 막힌 이유는 화면 위쪽 **출고 전 확인에서 막혔어요** 안내에 LOT별로 나온다.

근거 파일: `features/shipment/GoodsIssueScreen.tsx`

## 검수할 때 볼 것

- 메뉴 이름·버튼 이름이 화면과 같은지 (이 문서는 코드의 문구를 옮긴 것이다).
- 각 업무의 "하는 사람"이 [09] 역할·권한 표와 맞는지. 권한 이름은 화면 잠금 안내 문구를 따랐다.
- 🟡 표시한 곳.
- 이 매뉴얼을 AI 어시스턴트의 근거로 쓸지. 쓰려면 `process.generated.ts`처럼 생성 파일 방식으로 넣을지, 서버에서 직접 읽을지 정해야 한다 (`docs/backend/ai-assistant.md` 4장).
