# 서버 시드 (`server/prisma/seed.ts`)

조직·권한·기준정보·검사 기준만 넣는다 (코드 컨벤션 7-4). 수주·LOT·재고 같은 거래 데이터는 없다. 반복 실행해도 결과가 같다.

`--organization-only`를 붙이면 조직(직급·역할·권한·부서·사원)과 생산 설정값만 넣는다. 공용 DB(Supabase)는 이렇게 넣고 기준정보·검사 기준은 화면에서 등록한다(2026-10-08 결정, SERVER-GUIDE 8장). 생산 설정값은 등록 API가 없어(조회·수정만) 아래 초기값 1행을 넣고, 이미 있으면 그대로 둔다.

## 생산 화면용 거래 시드 (`npm run seed:demo -w @fantasteel/server`)

기본 시드를 넣은 빈 거래 DB에서 한 번 실행한다(수주·LOT이 있으면 건너뛴다): `npm run db:reset` → `npm run seed:demo -w @fantasteel/server`. 실제 서비스(수주 등록·실적 시뮬레이션·검사 등록)를 불러 만든다. 코드는 `server/src/seed/seed-production-demo.ts`.

| 대상 | 값 (가정값) |
|---|---|
| 원료 입고 | ORE01 1,500t × 2, COL01 600t × 2, LIM01 150t × 2, SMN01 20t × 2. 입고일 7일 전·3일 전(FIFO 확인용). 구매요청·발주·입고는 데이터로 직접 넣는다(입고 API 전) |
| 수주 1 | SS275 슬래브 250×1200×10000 10매 → 실적 시뮬레이션(시드 20261006)으로 연주까지, 계획 완료. 히트 1개·슬래브 8매는 검사 대기 |
| 수주 1 불합격 (불합격 관리 시연) | 수주 1의 앞 슬래브 2매만 검사 불합격(나머지 항목은 기준 범위 가운데 값). 1번째: 표면 결함 깊이 2.6mm(기준 0~2) → 처리 상태 보류, 사유 "표면 결함 깊이 재측정 전까지 보류 (시연용 시드)". 2번째: 두께 편차 +6.2mm(기준 ±5) → 처리 상태 미지정. 히트는 불합격시키지 않는다(하위 슬래브 10매가 모두 연쇄 불합격돼 검사 대기가 남지 않음) |
| 수주 2 | SM355A 코일 4.5×1500×544000 6개 → 시뮬레이션(시드 20261007)으로 연주까지 → 히트·슬래브 검사 합격(기준 범위 가운데 값) → 열연 투입 대기 |
| 수주 3 | SM355B 슬래브 220×1400×9500 8매 → 시작 전 계획 |
| 수주 4 (히트 불합격 시연) | SS275 슬래브 250×1200×10000 3매 → 시뮬레이션(시드 20261008)으로 연주까지 → 히트 성분 검사에서 인(P) 0.058%(기준 0.05% 이하)로 불합격. 히트 1개가 슬래브 10매를 만들어, 하위 슬래브 10매가 검사 없이 "불합격 히트의 하위 LOT"(TRM-078)으로 불합격 관리에 묶여 나온다 |

## 구매·업무·알림 화면용 거래 시드 (`seed:demo`가 생산 시드 다음에 실행)

화면 가짜 DB 시드의 구매 상태별 예시와 업무를 서버로 옮긴 것이다(메신저 대화방은 넣지 않는다). 업무나 이 시드의 구매요청(요청 근거 `시연용 시드 (구매 화면)`)이 있으면 건너뛴다. 실제 서비스(구매요청·승인·반려·발주·입고, 업무 등록·완료, 알림 읽음)를 불러 만들고, 날짜는 오늘(Asia/Seoul) 기준이다. 코드는 `server/src/seed/seed-collab-demo.ts`.

| 대상 | 값 (가정값) |
|---|---|
| 구매요청 (요청 정다은 → 승인·반려 최준혁) | 승인 대기 2(LIM01 120t, COL01 300t), 승인됨·미발주 1(ORE01 800t), 반려 1(SMN01 50t, 반려 사유 있음), 발주 → 부분 입고 1(SMN01 8t 중 오늘 5t 입고, 미입고 3t) |
| 업무 6건 | 예전 화면 가짜 DB 시드와 같은 제목·담당자·등록자·연결 화면. 마감일은 오늘 −1~+7일, 1건 완료(권예진 코일 야드 점검) |
| 알림 | 서비스가 보낸 승인 요청·결과 알림과 업무 지정 알림 5건(등록자 = 담당자인 1건은 알림 없음). 업무 지정 알림 2건은 담당자가 읽은 상태 |

## 3주 운영 이력 시드 (`npm run seed:history -w @fantasteel/server`) — 발표·시연용

기본 시드(조직·기준정보·검사 기준)가 들어 있는 DB에 10/1(목)~10/21(수) 3주치 거래·협업 이력을 넣는다. 코드는 `server/src/seed/seed-history-demo.ts`, 가상 시계는 `server/src/seed/virtual-clock.ts`.

- 거래 데이터가 있으면 건너뛴다. 지우고 넣으려면 `-- --wipe` (거래·협업 28개 표만 TRUNCATE. 조직·권한·기준정보·검사 기준·생산 설정값과 `past_case`·`meeting_minutes`·`schedule_event`·`integration_connection`·`ai_*`는 그대로 둔다. `past_case_lot`이 가리키던 LOT id는 끊긴다).
- 실제 서비스를 **가상 시계** 아래에서 날짜 순서로 부른다. 전역 `Date`를 바꿔서 서비스가 찍는 시각(created_at·approved_at·inspected_at·issued_at)과 채번 날짜(EV-YYMMDD, HT-BOF1-YYMMDD)가 그 시점으로 남는다 (Prisma 7은 `@default(now())`를 JS에서 채운다). DB `now()`를 쓰는 TypedSQL(재고 updated_at)만 끝에 맞춘다.
- `.env`가 Supabase를 가리켜도 실행된다 (`local-only.mjs` 가드 없음). 공용 DB에 넣는 것은 DB 담당자만, 팀에 알린 뒤 한다.
- 부팅 때 도는 예약 정합성 보정·Agent 감지는 끄고(`*_INTERVAL_HOURS=0`), 시드 끝에 10/21 09:50 시각으로 Agent 감지를 한 번 돌려 담당자 알림을 남긴다.
- 끝나면 `npm run check-invariants -w @fantasteel/server`와 `check-orphans`가 모두 통과한다 (2026-10-21 로컬 확인: 불변식 11개·관계 99개 위반 0).

| 주 | 내용 (모두 가정값) |
|---|---|
| 1주차 10/1~10/8 | 원료 구매 4건(요청→승인→발주→입고, 철광석은 1,800+1,200t 분할 입고) · SO-001 가람중공업 SS275 슬래브 18매(히트 2, 슬래브 1매 표면 결함 불합격→보류, 19매 합격·18매 예약·1매 여재) · SO-002 나래조선 SM355A 코일 7개(연주→검사→열연→코일 검사) · DR-001 출하·밀시트 |
| 2주차 10/8~10/16 | SO-003~006 등록(슬래브 20·SPHC 9·코일 15·슬래브 8) · MRP 근거 원료 구매 4건(철광석 2,000+1,500t 분할) · SO-003 슬래브 2매 불합격(폐기 1·보류 1)→재생산 PP-007 · SO-004 히트 인(P) 0.058% 불합격→하위 10매 연쇄→재생산 PP-008 · SO-006 취소(고객 요청) · SO-005 코일 15개 열연·검사 · DR-002~004 출하·밀시트 |
| 3주차 10/19~10/21 | SO-007 코일 9개(히트 2, 슬래브 16매 합격 → **열연 투입 대기**) · SO-008 슬래브 15매(재고 1 예약, 히트 2 생산, 히트만 합격·슬래브 16매 **검사 대기**) · SO-009 슬래브 12매(**시작 전 계획**) · 구매요청 승인 대기 2·반려 1·승인됨 미발주 1·발주 후 부분 입고 1 · DR-005 가람중공업 코일 15개 **배정 대기** · 업무 6건(완료 2) · Message → ERP 초안 1건 확인 대기 |

메신저: 수주 업무방 5개(SO-001·002·003·005·007, ERP 이벤트 시스템 메시지 포함), 그룹 2개(`구매·생산 원료 협의`, `10월 출하 조율`), 1:1 3개. 대화 내용은 시연용이며 `@AI` 호출은 넣지 않는다. 여재: SS275 250×1200 슬래브 1매(10/6부터), SM355B 220×1400 슬래브 8매(10/15부터), SPHC 1매, SM355A 250×1500 1매(SO-008 예약).

행위자는 역할대로다: 수주·출하요청·배정 영업(김도윤·박서영), 구매요청·발주·입고 정다은, 승인·반려 최준혁, 실적 시뮬레이션 강민석(열연은 한승우), 검사 서민지·오지훈, 불합격 처리 오지훈, 출고 권예진·신현우, 재생산 계획 강민석.

## 🟡 확인 필요

- **코일 길이 자리수:** ERD의 `item.length_mm`가 `decimal(8,2)`라 최대 999,999.99mm(약 1km)까지만 들어간다. 얇은 코일은 이보다 길 수 있어, 첫 코일 규격을 2.3mm×1,065,000mm(화면 시드 값) 대신 2.5mm×980,000mm로 잡았다. ERD를 `decimal(10,2)`로 넓힐지 정해야 한다.
- 가정값(부서·사원·치수·수율·원단위·거래처)은 팀 확인 대상이다.
